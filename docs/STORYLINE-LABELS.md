# Storyline labels — what the model costs, and what the floor looks like

Measured record for storylines-v2 S4 (ADR-0011, "Labels"). Numbers from the dev
archive on 2026-08-14: 22,987 articles spanning 2026-07-14 → 2026-08-14,
`APP_TIMEZONE=UTC`. Model numbers are from a live run against
`gemini-3.1-flash-lite` the same date; nothing in the test suite reaches the
live API. Reproduce with:

```bash
pnpm label:storylines --dry-run --limit=20
```

**Not `--preview`**, which this line said until 2026-08-28 and which S9 deleted
(see "What dies" below). The CLI ignores unknown flags, so the old command does
not preview anything — it labels 20 storylines for real, spending the calls and
writing the results. `--dry-run` is what reads without asking the model.

## What a label is

Two to five words naming a storyline at a glance — a proper noun plus what
happened: "Fort Hood Crash". Generated by the configured model at promotion, on
merge, and on drift; validated against ADR-0011's contract; falling back to the
bigram extractor and then to nothing. Presentation, never identity: nothing
keys off a label, two storylines may share one, and a null label renders. That
last clause is why an external model is tolerable here — the worst failure it
can produce is a storyline with no name.

## What gemma actually costs, measured 2026-08-28

Ten real dev-archive storylines, the repaired client (#177), the dev key, the
pacer off so these are latencies rather than pacing. **The whole table is a
function of one setting**, `GEMINI_THINKING_LEVEL`:

| | usable labels | median | thinking tokens | `MAX_TOKENS` |
| --- | --- | --- | --- | --- |
| field omitted | **3 / 10** | ~43 s | ~2,046 — the whole budget | **7 / 10** |
| `minimal` | **9 / 10** | **1.4 s** | **0** | **0 / 10** |

Left unset, this model is not "unconfigured" — it reasons itself into the token
cap on most prompts and answers nothing. Set to `minimal` it names nine
storylines in ten in under a second and a half. That is the finding this
document already recorded for the flash tier in August ("naming a story is
recall, not reasoning"), reached the other way round, and it is why
`GEMINI_MODEL` and `GEMINI_THINKING_LEVEL` are now a **pair**: gemma takes
`minimal` and 400s on `low`; 3.x flash takes `low` and 400s on `minimal`.

Three things worth keeping from the unset case, because they say what the
failure mode looks like if a future model reintroduces it.

**The 2,048-token cap is a circuit breaker, not a budget.** Re-running the
failures with `maxOutputTokens` at 8192, two reached **8,190 and 8,189 thought
tokens — 172 s apiece — and still answered nothing**, while the successes
reproduced to the token. `temperature` is 0, so the split is a property of the
prompt, not of sampling. Raising the cap converts a 43 s failure into a 172 s
one.

**It was not the prompt's shape.** Member count, group count, prompt size and
time span all overlap between the two groups: every success had exactly 2
members and so did 3 of the 7 failures; the **smallest** prompt in the set (226
tokens, 2 members, 0.1-day span) failed while a larger one succeeded. All four
storylines with 3+ members failed, but 2-member ones failed half the time too,
so at n=10 that direction carries nothing. Editing the prompt changed nothing
either — dropping the worked examples from the rules left the same storyline
running to `MAX_TOKENS` at 2,046 tokens, and adding `minimal` fixed it with the
examples still in place.

**A label costs ~1.4 s median** (mean ~3.9 s, pulled by one 19 s outlier), plus
2 s of spacing at 30 rpm. `CHORE_LABEL_BUDGET_MS`'s 240 s therefore admits
roughly 40–70 labels, which puts `CHORE_MAX_LABELS`'s 50 back inside the window
it was always meant to describe. With the field omitted it admitted about six.

**What this settles for [ADR-0011](adr/0011-a-storyline-is-a-persistent-arc-of-one-event.md).**
Configured correctly, gemma names 9 storylines in 10 at ~1.4 s against
flash-lite's ~0.9 s, at double the published rpm ceiling. The model choice
stands. What nearly cost it was a one-line default.

## The three triggers

| trigger | who decides | rule |
| --- | --- | --- |
| promotion | the linker (S3) | a second group attached; the storyline just became real |
| merge | the linker (S3) | two storylines became one, so the story changed shape |
| drift | `needsLabel` | member groups ≥ `label_group_count × STORYLINE_LABEL_DRIFT_FACTOR` (default 2) |

Promotion and merge are events a caller passes in. Drift is the only one this
layer decides, and it needs `storylines.label_group_count` (migration 0010) —
which cannot be derived, because `storyline_groups.attached_at` survives a
merge and so does not say when a group reached *this* storyline. The baseline
is stamped even when the label comes out null; otherwise a storyline nobody can
name is re-asked on every pass for ever, turning a storyline-volume cost into
an unbounded one.

**One exception, and it is not one: empty coverage.** A storyline whose member
articles have been retained away has nothing to show a model and nothing for the
extractor to read, so naming it returns before the model is reached and writes
*nothing at all* — no label, no baseline. The baseline records a JUDGEMENT
("asked, and no name came back"), and there is none to record here; stamping one
would hold the row nameless until its membership doubled, on a verdict nobody
gave. It costs one cheap read per pass and never a model call, so the unbounded
mode the paragraph above rules out is not in reach. The whole write, this branch
included, lives in `storyline-naming.ts`, which is the only caller of
`setStorylineLabel` — a rule the label columns need, because the two writers it
replaced had already answered this question differently.

## Choosing the model, measured

Three findings, none of which survived contact with a guess:

**`gemini-2.5-flash` 404s.** Still listed under `/models`, refuses on use ("no
longer available to new users") — exactly why the model id is config, not a
constant.

**`maxOutputTokens` counts thinking tokens.** The cap started at 32 (a label is
three words); against `gemini-3.7-flash` that returned an EMPTY candidate with
`finishReason: MAX_TOKENS`, the entire budget spent on thoughts. Now 256, which
costs nothing unless used.

**Thinking buys nothing here and bills as output.** Asked to name the Fort Hood
crash:

| model | thinkingConfig | thoughts | answer |
| --- | --- | --- | --- |
| gemini-3.7-flash | omitted | 463 | Fort Hood Crash |
| gemini-3.7-flash | `low` (its floor; `none`/`minimal` are 400s) | 300 | Fort Hood Crash |
| gemini-3.5-flash | `low` | 344 | Fort Hood crash |
| gemini-3.1-flash-lite | `low` | 121 | Fort Hood Crash |
| **gemini-3.1-flash-lite** | **omitted** | **0** | **Fort Hood Crash** |

Naming a story is recall, not reasoning. Flash-lite with the field omitted is
the default: same answer, no thinking tokens, cheapest tier. `GEMINI_MODEL` and
`GEMINI_THINKING_LEVEL` stay knobs because the families spell this differently
and a later model may need it.

**A fourth finding, two weeks later: thinking comes back as its own PART, and
the response shape moved under a pinned model.** Every response recorded on
2026-08-14 carried a single bare part, so the client read the candidate by
joining every part it found. On 2026-08-28 the same request, the same endpoint
and the same pinned `gemma-4-26b-a4b-it` returned two — `{"thought": true,
"text": "<the reasoning>"}` followed by `{"text": "Fort Hood Crash"}` — and the
join produced the transcript with the answer glued to its end. That is not a
two-to-five-word label, so `validateLabel` refused all of it and every storyline
took the bigram fallback: **0 model labels against 66 bigram ones in a day**, and
the failure was invisible because falling back is the designed behaviour for a
model that will not answer.

Two things worth keeping from it. *Pinning the model does not pin the response
shape* — the id is a promise about weights, not about JSON — so the client reads
the `thought` discriminator rather than trusting parts to be one thing. And *a
deterministic fallback hides the failure it exists for*: the label pass reported
success every night, which is why the bigram share, not the error rate, is the
number to watch (`check-chores.sh` prints it).

## Cost

Measured over 20 real day-bounded storylines: **712 input tokens per label**
(10 member headlines, descriptions trimmed to 200 chars), ~4 output tokens, no
thinking tokens at the defaults. Per 1,000 labels: ~0.71M input, ~0.004M
output. At the flash-tier rates published at the time of writing — $0.30/M
input, $2.50/M output —

    0.71M × $0.30  +  0.004M × $2.50  ≈  $0.22 per 1,000 labels

Unnoticed, `gemini-3.7-flash` at `low` would have added ~0.3M output tokens per
thousand — ~$0.75, quadrupling the bill for an identical answer. The rates may
go stale; the token counts are measured. Even a tenfold error either way leaves
this a rounding error, the only property the decision rests on.

Volume is small by construction: 3,437 multi-group day-bounded storylines over
32 days (~107/day) is a generous CEILING for v2 promotions, since a v2
storyline persists and is promoted once where the old day-bounded model
re-formed daily. At ~110 labels/day the bill is around **$0.02/day**. Labels
run at storyline volume; the linker runs at group volume (~1,200/day) and is
deliberately not a model call (ADR-0011, "Considered and refused").

## The rate limit, and where it is enforced

The free tier publishes **15 requests per minute**, and the ceiling is on the
KEY — which is why the pacer lives in `gemini.ts`, not in the callers. Five
things label storylines:

| caller | where it runs | when |
| --- | --- | --- |
| the ingest tail (`labelLinkedStorylines`) | the server | promotion and merge, off the §6.3 deadline |
| the late-candidate sweep | `pnpm chores storylines` | nightly, before the drift pass |
| the drift chore (`labelPass`) | `pnpm chores storylines` | nightly |
| `pnpm backfill:storylines` | its own process | an operator, on the whole archive |
| `pnpm label:storylines` | its own process | an operator, on what needs it |

Before this they were paced separately or not at all: the two nightly passes
spaced at 60/min (four times the ceiling), the ingest tail and sweep had no
spacing, and retries were invisible to all four — a bad minute at the API
multiplied the real rate by up to 3. One pacer inside the client fixes the
category of bug rather than four instances of it.

**The pacer's scope is one client, so one process.** The server's ingest tail
uses the instance built in `server.ts`; the chore runner and each CLI build
their own from `wiring.createLabeler`. Two of them running at once is two
pacers each admitting `GEMINI_MAX_RPM` — up to 2x the ceiling (3x with three);
the 429 path below is what holds the key then. The nightly runner is the case
nobody chooses — 04:00 UTC arrives whether or not the server is labelling — so
it takes `--label-rate` like the backfill (STORYLINE-BACKFILL.md, "Operating
it"). Note that `--max-labels` bounds only the drift pass: the sweeps relabel
whatever they merge or attach, and that spend is bounded by what moved.

It is a sliding 60-second window, not a per-minute counter — a counter
resetting on the minute admits a full limit at :59 and another at :01 — and
slots are reserved before the wait, so two callers arriving in the same tick
stack instead of both reading a window with room in it.

Three properties worth knowing:

- **A 429 holds the whole client back.** Earning one despite the pacer means
  something else is on the key, so `Retry-After` becomes a cooldown every
  waiter respects — including waiters ALREADY ASLEEP when it lands: a waiter
  re-reads the cooldown on waking and sleeps again if it moved, because one
  that only checked before sleeping would wake inside the cooldown and send the
  request it exists to stop. Cost: held waiters resume together at the
  cooldown's end rather than re-spacing; the window paces everything after
  them.
- **The queue is bounded.** Past `GEMINI_MAX_RATE_WAIT_MS` (2 minutes — ~30 deep
  at the 15/min this was written at, ~60 at today's 30) a call gives up and
  takes the bigram fallback — the same move as for a 503. Otherwise the ingest tail would grow an unbounded queue during a
  promotion burst, each waiter holding its members in memory. Cost: a sticky
  bigram label — the baseline is stamped either way, so drift will not re-ask
  until membership doubles; `--relabel` is the repair. The CLIs raise the cap
  to 15 minutes, since a backfill would rather wait than settle for a bigram.
- **Serially, latency binds before the limit does.** At ~7.1s per call a single
  pass sustains ~8.5 labels/min, under 15 and further under today's 30. What a
  serial pass sustains on gemma is **not currently known** — the 2026-08-28
  attempt to measure it timed failing calls, not labels (see the note at the top
  of this file) — which is exactly why the 300 s window wants a wall-clock bound
  rather than a count (`.env.example`, `CHORE_MAX_LABELS`). The ceiling only
  binds on a
  parallelised pass — exactly what STORYLINE-BACKFILL.md recommends for a full
  relabel, and why the pacer has to be in the client such a pass would share.

`GEMINI_MAX_RPM` is the knob; raise it with the plan and every path above
follows, including the nightly passes, which take it as their spacing.

## What the model produces, measured

20 day-bounded storylines, live, at the defaults: **17 model labels, 3
fallbacks, 0 unnamed.** Against the same storylines, the extractor alone:

| model | bigram fallback |
| --- | --- |
| Trump Executive Orders | Executive Order |
| Hormuz Strait Crisis | Strait Hormuz |
| Ukraine Russia Escalation | Ballistic Missile |

| Gaza Disarmament Standoff | Gaza Hamas |
| Europe Wildfire Crisis | France Spain |
| USS Lincoln Crisis | Uss Abraham |
| AI Memory Race | Ai Memory |
| Canada US Tensions | Social Media |

The left column names events; the right names entities, or nothing — ADR-0011's
justification for the model, reproduced on live output.

Three qualifications, all honest:

- **Three failures in twenty**: one 503 (retried, still 503), one lost to the
  8s deadline — now 20s — and one contract refusal, "Osun Election 2026",
  refused for a digit on a rule ADR-0011 never wrote. Two of three fixed; the
  503 is what the fallback is for.
- **Garbage in, plausible out.** "Market Trends August" and "Global Weather
  Events" came from day-bounded storylines the OLD model had swallowed — 68 and
  33 unrelated groups. They pass validation ("August" is capitalized and
  grounded) and name nothing. Grounding cannot catch this; a real v2 storyline,
  formed err-narrow, is a different input.
- **One label looked invented and was not.** "Ceuta Migrant Crisis" named a
  day-bounded storyline whose newest headline is about Netanyahu — but Ceuta
  appears in 5 of its 12 headlines: the model found the plurality story inside
  a swallowed storyline.

Casing is not normalized on model output ("Infantino leadership crisis" came
back part-lowercase): forcing Title Case would break names that carry their own
case, and this is presentation that regenerates. Left alone deliberately.

## The fallback floor, measured

With no `GEMINI_API_KEY` the preview labels **30 of 30** day-bounded storylines
from the bigram extractor. Freeing it from ADR-0010's containment rule fixed
the yield problem outright — the old rule produced 9 phrases from 46 eligible
slots — but yield was never the hard part. A sample:

| label | what it is |
| --- | --- |
| Karoline Leavitt | a person, not an event |
| Strait Hormuz | a place, not an event |
| Berkshire Hathaway | a company, not an event |
| Social Media, Price Target, Wall Street, World Cup | generic pairs |
| Ai Help, Ai Memory, Hit High, Tens Thousands, Investing Com | not names of anything |

Roughly two thirds contain a proper noun and almost none name a happening: the
extractor cannot reach "names the event at a glance", and that gap is the
justification for the model. It is the floor, not the target.

(The day-bounded storylines come from the OLD model, borrowed by `--preview`
because the v2 linker did not exist yet. Some are visibly swallowed — 76 groups
under "Executive Order" — ADR-0009's measured failure, not the labeler's.)

### Gated on proper-noun evidence (2026-08-20, issue #100)

A live sample found **323 of 323** stored bigram labels passing the extractor's
own shape-and-vocabulary rules while a 60-row read showed zero as "a proper
noun plus what happened": bare entities (`Red Sox`), categories (`Earnings
Call`), and fragments (`Golen Scores`). The rules being passed cannot measure
what ADR-0011 actually cares about — a bigram is grounded in the coverage it
was lifted from BY CONSTRUCTION, so grounding tells the extractor nothing a
model answer's contract needs told.

`bestBigram` now refuses to choose a phrase unless one of its two words
carries `properNounEvidence` over the storyline's own coverage — the stricter
corpus-case test the label-agreement merge already uses above, not the Title
Case that every word in a headline wears for free. Two mechanical gaps went
with it: the verb gate now also catches a bare lemma ("agree", not only
"agrees"/"agreeing"), and adjacency is computed over the true token stream
rather than the stopword-filtered one, so a stopword between two words no
longer reads as though they stood together ("agree deal" out of "royals …
agree to a deal").

Punctuation fabricates adjacency the same way and needed the same treatment.
The tokenizer DISCARDS its delimiters, so "Ukraine, Russia talks resume"
leaves `ukraine` sitting next to `russia` with nothing left to show that a
comma stood between them — and the proper-noun gate cannot catch that one,
because both halves really are names. Pairs are now drawn from RUNS of words
that nothing but whitespace separated, which also handles the spaced hyphen
feed titles use as a source separator ("Bitcoin rise continues - Reuters").

`properNounEvidence` needed one more clause to do the job asked of it here.
Ignoring the segment's first capital is not enough to neutralize Title Case:
every LATER word of a Title Case headline is a mid-segment capital too, so on
a storyline whose members are Title Case with no descriptions the test
promoted every word and admitted exactly the vocabulary pairs it was added to
refuse — "Second Quarter Eps Estimate Revised Again" still yielded `Eps
Estimate`. What makes a capital mean something is a segment that would have
shown a common word lowercase, so evidence is now taken only from segments
that show at least one. A corpus that is Title Case throughout yields no
evidence rather than promoting all of it.

The bare lemma needed a list of its own. Membership of `VERB_LEMMAS` is
decided on the -s and -ing forms, and the bare form is a fourth inflection
that nominalizes on its own schedule — "rises"/"rising" name nothing but "a
pay rise" is a noun, as are "paid leave", "a hail storm", "a work permit", "a
product recall". Gating those does not rank a phrase lower, it removes the
label entirely, so `BARE_NOUN_LEMMAS` takes them back out and only an
unambiguous predicate keeps the bare route.

Not re-measured against the live archive — this is a mechanism change, not a
new sweep. The expected effect is the one the issue already named: fallback
yield drops, real storylines go unlabelled more often, and the cloud shrinks —
traded for a floor that stops manufacturing names. A null label still renders
(ADR-0011, "Labels"), which is what makes the trade affordable.

### Lexicon gaps behind the gate (2026-08-20, issue #100 follow-up)

The gate above is only as good as the lexicon it reads, and a live check after
both gate-fix commits landed found labels still passing it: `Rangers Beat`,
`Gigabyte Brings`, `Danon Blames`, `AGL Jumps`, `Fire Rips`, `Boxer Dies`.
Every one is a verb the lexicon simply did not contain, so `beat`, `bring`,
`blame`, `jump`, `rip` and `die` were added by the file's own test — does the
-s/-ing/bare form nominalize? — with `blame` and `rip` keeping their bare forms
via `BARE_NOUN_LEMMAS` ("the blame", "a rip") and `beaten` added to
`IRREGULAR_PAST`, which no -ed rule reaches.

`jump` was the interesting one: it was ALREADY in the file, classified
PAST_ONLY on the reading that "ski jumps" is a plural noun. "AGL Jumps" says
the other reading is live too. Both are real, so it moved to
FINITE_ONLY_LEMMAS — gated on -s and -ed, -ing left alone, since "show
jumping" and "ski jumping" are where the nominalization actually sits. One
classification per lemma; a lemma in two lists is two contradictory answers,
and the more permissive list silently wins.

Two of these exposed spelling bugs in `participles`, which matter more than a
missing lemma because a misspelled form gates nothing while looking present:

- **`-ie` derived "diing", not "dying"** (and had been quietly doing it to the
  pre-existing `vie` → "viing").
- **`-ee` derived "agreeed", not "agreed"** — the bug this issue named in
  passing, still live until now. It cost `agree` and `disagree` their past
  route, and `guarantee`, which is PAST_ONLY, the only route it had; a corpus
  saying "the terms were agreed in Kelowna" yielded `Kelowna Agreed`.

Deliberately left ungated: `hold`, `attempt`, `top`, `set`, `call`, `ban`,
`open`, `score` also appear in clause-shaped labels, but their -s/bare forms
are genuine headline nouns (escape attempts, mountain top, TV set, travel
bans, The Open, game score), so gating them would cost real compounds under
the asymmetric-cost rule. Accepted false negatives, like `hold` and `ban`
before them.

`beat` and `die` keep their bare forms gated, which is the one place this
trades a real noun away ("earnings beat", "the crime beat", a semiconductor
"die"). It is affordable because a bigram needs proper-noun evidence to be a
candidate at all: `Earnings Beat` has none and was already refused, while the
pairs that DO clear that bar — `Rangers Beat` — are the clauses.

Not re-measured against the live archive; same reasoning as above, this is a
vocabulary change, not a new sweep.

### The two holes still open behind it (2026-08-21)

A `--labels-only` campaign after a full storyline rebuild left six live
storylines on `label_source = 'bigram'`, and four of them still stated
something: `Neto Homers`, `Gigabyte Brings`, `Brewers Place`, `Lufthansa
Discover`. All four reproduce offline from the members' own titles and
descriptions, and they split evenly across two different holes.

**The lexicon, again — including its bare-form rule.** `homer` was absent
outright. `place` was present and classified PAST_ONLY, on the sound reading
that "places" is a plural noun and "a place" is a noun too. What both have in
common is the shape that reading prices as unreachable: headline style puts a
plural subject in front of the BARE verb, and in a headline a plural subject is
a team. "Brewers place RHP Abner Uribe (forearm) on 15-day IL". "Albies and
Riley homer, Braves beat Marlins 4-2". Neither predicate is inflected at all,
so no -s, -ing or -ed route reaches it.

Both are gated now, bare form included, on the same asymmetry `beat` and `die`
were decided on: the nominal reading takes a numeral or an adjective in front
of it, never a name, and a bigram needs proper-noun evidence to be a candidate
at all — so the only pairs that clear that bar are the clauses. `place` MOVED
to VERB_LEMMAS rather than being copied there; a lemma in two lists is two
contradictory answers with the more permissive one silently winning.

Sweeping the same archive for the same shape found 24 more lemmas missing and
2 classified where their -s could not gate. Twenty-two are ordinary verbs the
file simply lacked (`acquit`, `activate`, `add`, `chastise`, `confer`,
`convey`, `deepen`, `demolish`, `disarm`, `fade`, `induct`, `intensify`,
`laud`, `liken`, `misrepresent`, `neutralize`, `resurrect`, `revert`, `shrug`,
`withdraw`, plus `near` and `overhaul` keeping their bare forms via
`BARE_NOUN_LEMMAS` — "Near Bordeaux" heads 17 live labels and "an overhaul" is
a plain noun). Three went to FINITE_ONLY_LEMMAS because the -ing is where they
nominalize: `ask` ("an asking price"), `bake` ("baking soda"), `clear` ("a
clearing"). And `ok` is there for its -s alone: "Senate OKs" and "ERC OKs" are
a live headline idiom, `oks` is no kind of noun, and the bare form is an
interjection before it is anything else.

**The case override was nearly free.** `brings` and `discover` were both
already in the lexicon. What admitted them is the guard that keeps "Ken Burns"
and "Patriot Games": a word with `properNounEvidence` is never read as a verb,
because corpus case outranks the lexicon. On a storyline of two or three
members that evidence costs almost nothing, and it costs nothing at all in one
shape — a press release quoting its own Title Case headline inside its body.
"GIGABYTE Brings AORUS INFINITY to Gamescom 2026" reappears mid-description,
the sentence split glues that Title Case run onto the prose sentence after it,
and one article supplies both the mid-segment capital and the lowercase word
that makes the segment count as prose.

So `properNounEvidence` now counts MEMBERS rather than occurrences, and the
bigram label reads it at two bars. The grounding gate keeps the old one: it
asks "is either word a name?", where a wrong refusal costs a real label
outright. The verb gate asks for two members, because there a wrong `true`
admits a clause the lexicon had already caught. An article echoing itself is
one source.

Measured over 3,471 live multi-group storylines relabelled offline from their
own coverage — no campaign was run; the four bad labels reproduce without
spending model quota. Together the two changes move 43 labels and take yield
from 89.2% to 88.9% (3,097 → 3,085 of 3,471):

- **The lexicon: 30 labels, and all 30 of the old ones were clause-shaped.**
  No name was lost. Ten are withdrawn outright and 20 are replaced, mostly by
  a name from the same headline (`Hamas Disarms` → `Gaza Plan`, `Senate
  Clears` → `Russia Sanctions`, `Gigabyte Brings` → `Aorus Infinity`).
- **The override bar, 1 → 2 members: 13 labels.** Nine clauses refused
  (`Gigabyte Brings`, `Jpmorgan Warns`, `Apple Wants`, `Market Wakes`,
  `Paramount Mulling`, `Showrooms Coming`, `Bounce Fades`, `Erc Oks`, `Senate
  Oks`), one improved (`Keeping Score` → `Aoc Woke`), two swapped on
  storylines that are piles under either name (`Grand Slams` → null,
  `Lufthansa Discover` → `Alaska Airlines`), and **one real name lost**:
  `Flying Eagles` → `Eagles Cruise`. The team name was carried by a single
  member, and `cruise` is a noun as often as a verb, so the lexicon cannot
  catch what replaced it.

Not three members. That bar costs `Justin Rose` — a golfer who survives today
only because the override outranks `rose` in `IRREGULAR_PAST` — and buys
nothing else: it is the only label that moves, and it moves to `Memphis
Bucking`.

`Lufthansa Discover` is the honest loss on the naming side rather than the
mechanism's: "Discover Airline" really is the carrier's name and `discover`
really is a VERB_LEMMAS entry, so the override was doing its job on one
member's word. That storyline is a pile of two unrelated airline stories under
either name.

Still open, and deliberately: `Rangers Jacob`, from "Rangers' Jacob deGrom
surpasses 2,000 K's …", which is not a verb-gate failure at all —
`trimWordPunctuation` strips the possessive and leaves `rangers` sitting beside
`jacob` in one token run, so the extractor cuts a person's name in half across
a punctuation boundary the source text did write. Same shape as issue #100's
comma finding, and a `tokenRuns` question rather than a lexicon one.

It is left separate because it is not the same bug wearing a different hat, and
the obvious fix may be wrong. A comma fabricates adjacency; a possessive
asserts a relation, and severing the run would also stop "Trump's tariffs" from
proposing `Trump Tariffs`. 2,224 texts in the archive write a possessive
directly before a capitalized word, and 31 write "Trump's tariff" specifically
against 54 for the bare "Trump tariff" — so the blast radius is wide and the
good cases are real. What is actually wrong with `Rangers Jacob` is narrower
than the punctuation: `jacob` is a FIRST name, and its bigram partner should
have been `degrom`. That wants its own measurement, and possibly its own rule.

`Francisco Lindor`, the sixth, is a well-shaped label on a storyline that is a
pile of unrelated baseball games. That is formation, not naming.

One thing this change found the hard way: a verb-lexicon edit is **not**
label-only any more. `stripSourceAttribution` decides whether a title's
trailing segment is the outlet's name partly by asking the same lexicon
whether the segment states something, and `headlineTokens` peels before it
tokenizes — so a new lemma can move the stored vocabulary. Diffed across all
28,294 distinct titles in the archive, exactly one moves: `homer` stops "Andrea
Cline Obituary - Homer Glen, IL" being peeled, and the town survives into the
tokens (which is the better reading of that title anyway). `TOKENIZER_VERSION`
goes to 7 for it, with the repair scoped in `grouping.ts` — one row's backlog
does not buy a storyline restart. Anything touching verb-lexicon.ts from here
needs that diff before it can call itself label-only.

## What is validated, and what is not

`validateLabel` enforces three of the contract's four clauses:

- **2 to 5 words**, after stripping the quotes and emphasis a model wraps an
  answer in — but not the apostrophe inside Xi'an, part of the name.
- **No punctuation**: letters, digits, spaces, and the hyphen/apostrophe that
  live inside names. A sentence fails here, which is how a chatty answer is
  caught. Digits are admitted on live evidence ("Osun Election 2026"): the
  contract bars punctuation and a year is not punctuation.
- **Contains a proper noun**, enforced as GROUNDING: at least one capitalized
  word must appear in the coverage it names, under the same singular fold the
  rest of the system uses. Corpus case evidence (`properNounEvidence`) was the
  alternative and is too strict for validation — conservative by design, and
  headlines are Title Case, so a storyline whose members carry no descriptions
  would fail every label. Grounding catches the failure that matters: a name
  appearing nowhere in the story.

The fourth clause — **names the event, not just the entity** — is not enforced
because it is not checkable: "Fort Hood Crash" and "Donald Trump" are both two
capitalized grounded words, and no test over tokens separates them. The prompt
carries the clause and live output judges it; ADR-0011 says the prompt iterates
and the contract does not. `storyline-label.test.ts` states this as a passing
test rather than leaving it to be found as a bug.

## The label as merge evidence

A label is presentation, not identity — but two labels *agreeing* turned out to
be the only usable evidence for a merge the token rules cannot reach.
ADR-0011's "Labels" section carries the amendment; this is what the archive
said.

**The problem.** The merge is ADR-0011's only cure for err-narrow formation,
and it needs a group that straddles two arcs — which fails exactly where it is
needed most. On 2026-08-17 the archive held the Strait of Hormuz coverage as
**25 live arcs** whose entire shared vocabulary was `{hormuz, strait, iran}`
(linker-side analysis: docs/STORYLINE-LINKING.md, "The anchor ceiling cannot
reach a big running story"):

| token | df | share of a 17,028-article fortnight | anchor ceiling |
| --- | --- | --- | --- |
| `hormuz` | 422 | 2.5% | 34 (0.2%) |
| `strait` | 363 | 2.1% | 34 |
| `iran` | 703 | 4.1% | 34 |

Mass 10.7 against a floor of 20, not one token able to anchor: no group can
bridge them, nothing merges. The story's own name had outgrown the rule meant
to recognize it. **The labeler had already solved it**: six of those arcs were
independently given the identical name "Strait of Hormuz Crisis".

**What agreement alone would have cost.** The same archive gave three arcs the
label "Q2 2026 Financial Results" — CVB Financial, Mitsui, Mayfair Gold,
Westaim, unrelated companies reporting earnings. Their spans overlap, so
ADR-0010's date-span disambiguator does not separate them: the "garbage in,
plausible out" failure above, arriving where it can do damage.

**What separates them.** `properNounEvidence` — the corpus-case test rejected
above for label *validation* as too strict:

| label | words with proper-noun evidence | verdict |
| --- | --- | --- |
| Strait of Hormuz Crisis | `hormuz` | merge |
| Q2 2026 Financial Results | none | refused |

"Hormuz" is never written lowercase in the coverage; "financial", "results" and
"quarter" always are. The conservatism wrong for validation is right here: a
refused merge leaves two storylines — the status quo — where a refused *label*
leaves a storyline nameless.

**Both sides must fold a word the same way**, and for a while they did not. The
gate compares label words against corpus words; the corpus tokenizer strips a
possessive (`Dillard's` → `dillard`) while `normalizeLabel` only ran `singular`
— dropping the final `s` and stranding the apostrophe: `dillard'`. The gate was
asked for a token the corpus could never hold and refused a real name as no
name at all. Measured: two arcs of one earnings story, both labelled "Dillard's
Tariff Refund Earnings", refused for "no grounded name" while `dillard` sat
capitalized in their own coverage. Fixed by giving both callers one fold
(`trimWordPunctuation`) rather than a second regex — the same reason the two
layers share `singular`. Any possessive label was affected, and a plural
possessive ("Workers' Rights" → `workers'`) fails the same way if only `'s` is
stripped.

**The rule** — four clauses, each refusing something the others cannot see:

1. Both labels from the **model**. The bigram fallback named sixteen unrelated
   arcs "Strait Hormuz" — agreement about vocabulary, the anchor rule's
   business.
2. Labels **equal** after casefolding, whitespace collapse and the `singular`
   fold. Stopwords are deliberately *not* elided.
3. The label contains a **grounded proper noun**, pooled over the component's
   whole coverage.
4. Spans **overlap or fall within `STORYLINE_LABEL_MERGE_GRACE_DAYS`**.

Transitive within one label and nowhere else: three arcs chaining A–C–B
collapse together, because C covers the gap and all three carry one name. The
label is the boundary — what makes this bounded where ADR-0009's transitive
token linking was not.

**Measured on the dev archive** (2026-08-17, 258 model-labelled live
storylines):

| label | arcs | grounded names | outcome |
| --- | --- | --- | --- |
| Strait of Hormuz Crisis | 6 | `hormuz` | merged into one 31-group arc |
| Q2 2026 Financial Results | 3 | none | **refused** |

Two shared labels, one merge, one refusal — the refusal being the load-bearing
half. Yield is small only because most of the archive is unlabelled (13,390 of
13,648 live storylines have no model label); under the nightly label chore
every promoted storyline carries one.

### The grace window, measured

`STORYLINE_LABEL_MERGE_GRACE_DAYS` was unmeasured while every arc of the one
qualifying component overlapped every other. The label backfill (2026-08-17,
855 model-labelled live storylines) produced what the knob needed: two shared
labels whose arcs are separated by a real gap, wanting **opposite** answers.

| label | gap | what it is | should merge |
| --- | --- | --- | --- |
| Kyle Shanahan car crash | 12d (Jul 30 → Aug 11) | the crash, then the admission of fault | yes |
| Canada US tariff talks | 19d (Jul 24 → Aug 12) | two rounds of a recurring negotiation | no |

The gap does exactly the work ADR-0010 gives it: a story that stops and
restarts is one storyline; a negotiation that comes back around is not, and the
only thing separating those cases is how long the silence ran.

**14 is the only setting that gets both right** — 7 refuses the Shanahan merge,
20 accepts the tariff merge. The value now rests on data, but on a sample of
two; a third separated component is worth re-reading it against.

Why it went unmeasured so long is worth naming: it needed a *large* labelled
archive, not a clever test. At 258 model labels there were two shared labels
and no gap between any pair of arcs; at 855 there were four, two separated. The
knob was untestable until the backfill ran.

### Fired by the collision, not only by the clock (2026-08-21)

The merge was a nightly chore because the evidence only exists after the label
is written — which makes a **label write the exact moment a collision can come
into being**, and the ingest tail is standing right there holding the name. On
2026-08-21 the gap between those two facts was measured the unpleasant way: an
afternoon backfill left six live arcs named "Canada US Trade Talks" (sixteen
duplicates across six labels) standing on the front page until an operator ran
the CLI by hand, because nothing was scheduling the chore at all.

So the tail now asks (`storyline-label-merge-trigger.ts`): after
`labelLinkedStorylines` writes a batch's labels, each model-written name gets
one GIN-indexed count of its live holders, and a name held by
`STORYLINE_LABEL_MERGE_TRIGGER` or more storylines (default 2; 0 turns the
trigger off) fires the same `mergeAgreeingLabels` pass the chore runs — scoped
to that one label. The decision is unchanged by construction: one planner, one
grounding guard, one grace window, one component valve, whichever caller asks.
The trigger changes *when*, never *whether*.

Three properties make it safe on the ingest tail:

- **Cheap when nothing collides**, which is almost always — one indexed count
  per label written; the candidate and coverage reads are paid only on a hit.
- **Concurrency by inheritance** — `mergeStorylines` serializes every merge
  behind its advisory lock, so two tails firing on one label degrade to one
  merging and one no-op.
- **It follows the survivor.** A relabelled survivor can land on another live
  arc's name — observed the same day: the pass-one survivor was re-named
  "Canada US Trade Talks", colliding with the arc it had not merged with — so
  the trigger re-counts each survivor's new name and runs again, bounded by a
  round cap of 4. Each merging round shrinks the number of live storylines,
  which is what makes the loop terminate without the cap.

Two costs it does not hide:

- **It counts a different column than the planner reads.** The count is a GIN
  scan over `label_words`; the planner reads `label` and folds it in JS. Those
  agree only because `setStorylineLabel` writes both — a labelled row that
  predates migration 0016 and never had `backfill:label-words` run against it
  carries `'{}'`, is invisible to the count, and so does not fire a trigger the
  nightly pass would still catch. Measured 2026-08-21: 0 of 298 eligible
  labelled storylines on the dev archive carry empty `label_words`, so the gap
  is closed there by the backfill having been run, not by construction.
- **It lengthens the one job that waits for the tail.** `processSampleJob`
  (§10.1) awaits the label tails before clearing the trending cache, and the
  consumer runs at concurrency 1, so a sample that triggers a merge holds the
  only worker for the merge rounds too — model relabels included. Free in the
  ordinary case, where nothing collides; the lever if it bites is the consumer's
  concurrency, not dropping the await.

The threshold is 2 and should stay 2: of the six collision components the
backfill produced, three held exactly two arcs, and a higher value leaves every
pair standing until a scheduled pass runs. 1 is refused outright — a shared
label needs two holders, so it would pay a candidate read per label and never
merge. The nightly chore keeps running as the unscoped backstop — a crashed
tail, a disabled trigger, a row the backfill never reached, or a collision
assembled by drift relabels still needs a pass that asks about everything.

## Operating it

```bash
pnpm label:storylines                  # label promoted storylines that need it
pnpm label:storylines --dry-run        # say which, write nothing
pnpm label:storylines --preview        # read-only quality/cost harness (dies in S9)
pnpm merge:storyline-labels --dry-run  # what the label-agreement merge would do
pnpm merge:storyline-labels            # merge it, and re-name the survivors
```

The dry run prints every shared label with its grounded names and every arc's
span, then the plan and the refusals. Merging has no inverse (ADR-0011 refuses
split), so reading that output is the check — and the refusals are where a
generic model label shows itself.

With no `GEMINI_API_KEY` every path still runs; the model is never asked and
`source` reads `bigram` throughout. Tests never reach the live API: the client
is exercised against recorded payloads in
`fixtures/gemini-label-responses.json`, every shape confirmed against the real
endpoint during the run above.

Latency: ~8s per call end to end over the 20-label run — why the deadline is
20s and why labelling is a background pass, never on a reader's path.
